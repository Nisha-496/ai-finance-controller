# Demo dataset — talking points

Generated by `scripts/generate-data.ts` (seed `20260902`, 25 deals). Regenerate anytime
with `npm run script scripts/generate-data.ts` — it's deterministic, so the same seed
always produces the same rows.

This set is small and meant to be walked through live. For measured accuracy numbers,
use `data/eval/` instead (held out, never shown here) — see ARCHITECTURE.md Section 7.

## Rows worth pointing at during the walkthrough

Open `orders.csv` / `transactions.csv` / `settlements.csv` and look for:

- **Format mismatch, still an exact match** — an order like `order100004` and its
  settlement referencing `txn_100004` in a different style than the transaction row.
  Should resolve to `MATCHED`, confidence 100, via normalization alone.
- **Fuzzy recovery** — a settlement whose `transaction_ref` has a 1-digit typo against
  the real transaction. Should land as `MATCHED` via the fuzzy path, not exact.
- **Genuine amount mismatch** — a settlement whose gross amount is short of the
  payment by ₹50–500, unexplained by fee/tax. Should raise `AMOUNT_MISMATCH`.
- **Missing settlement** — a transaction with no settlement row at all.
- **Missing payment** — an orphan settlement row with no matching order/transaction.
- **Duplicate settlement** — two settlement rows (`STL-xxxxxB` suffix) claiming the
  same transaction reference. Should be flagged `DUPLICATE_TRANSACTION`, not
  auto-matched to either.
- **Pending** — a transaction with `status = PENDING` and (correctly) no settlement yet.

Run the generator output log to see the exact scenario mix for this seed.
